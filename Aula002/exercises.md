**1.** Não é escada porque linguagens não "evoluem" pra melhor versão de forma linear, várias convivem, cada uma boa em domínio diferente (ex: Fortran pra cálculo numérico). Dois fatores: (a) contexto histórico/hardware da época limitava escolhas de projeto; (b) linguagem antiga continua em uso (legado, base instalada) mesmo quando surge outra melhor, então influencia sem sumir.

**2.** Plankalkül nunca rodou em máquina real na época, mas foi primeiro projeto de linguagem de alto nível já com ideias avançadas. Três recursos antecipados: tipos de dados estruturados, arrays, e atribuição/estruturas de controle parecidas com linguagens modernas.

**3.** Short Code e Speedcoding eram interpretadores (código mais legível, mas rodava lento, interpretado linha a linha). Sistemas A-0/A-1/A-2 (Grace Hopper) já geravam código de máquina a partir de instruções mais simbólicas, mais perto de compilação real, só que ainda bem primitivos, sem otimização. Chamar todos de "compiladores modernos" é impreciso porque não faziam análise/otimização como compilador atual; eram tradutores simples.

**4.** Fortran precisava provar que código gerado automaticamente era tão rápido quanto assembly escrito à mão, senão ninguém trocava, na época performance era tudo já que o hardware era caro e lento. Relação: se compilador gerasse código ruim, custo de programação cai, mas desempenho cai também, o que não compensava pros usuários da época. Adoção só veio quando ficou claro que dava pra ter os dois.

**5.** Fortran nasceu pra cálculo numérico/científico (dados numéricos, arrays, loops). Lisp nasceu pra IA, foco em manipulação simbólica, listas como estrutura central, não números. Fortran é imperativo/procedural; Lisp favorece recursão e tratar código como dado.

**6.** Contribuições de ALGOL 60 que passaram do mercado: (a) sintaxe formal com BNF, usada até hoje pra definir linguagens; (b) estrutura de blocos aninhados (escopo léxico), base de linguagens modernas; (c) recursão como conceito formalizado. Não dominou mercado (poucas empresas adotaram comercialmente) mas moldou desenho de quase toda linguagem imperativa depois, influência não depende de popularidade comercial, depende de quem lê/estuda o projeto da linguagem.

**7.** Cobol foi feita pra gente de negócios, não cientistas, por isso sintaxe verbosa, quase inglês, buscando legibilidade por quem não é programador. Registros (records) vêm da necessidade de representar dados comerciais (nome, endereço, valor) de forma estruturada. Herdou de FLOW-MATIC ideia de comandos parecidos com frases em inglês.

**8.** Basic buscava simplicidade pra ensinar iniciantes (ambiente acadêmico, sintaxe mínima). PL/I tentou ser "tudo em um", unir recursos de Fortran, Cobol e Algol num pacote só, mirando programadores profissionais em várias áreas. Trade-off: Basic sacrificou poder por facilidade; PL/I ganhou poder mas ficou complexa demais, difícil de implementar bem.

**9.** APL: foco em notação matemática compacta pra manipular arrays/matrizes, contribuição duradoura: operações vetoriais nativas (influenciou linguagens de array como R, NumPy). SNOBOL: foco em processamento de strings/pattern matching, contribuição: casamento de padrões avançado. SIMULA 67: foco em simulação de eventos, contribuição: introduziu classes e objetos, base da programação orientada a objetos.

**10.** Ortogonalidade é quando um pequeno conjunto de recursos primitivos combina livremente entre si, sem regras especiais/exceções. ALGOL 68 levou isso ao extremo, muito regular, mas resultado ficou difícil de entender/usar porque tantas combinações possíveis viram complexo pra leitura humana. Então não: ortogonalidade alta não é sinônimo de fácil de usar, pode ser o oposto se virar regras demais combinando.

**11.** Cadeia: ALGOL → Pascal (Wirth simplificou ALGOL pra ensino, manteve blocos e tipagem) → C (Ritchie pegou ideias estruturais mas focou em eficiência/baixo nível, ligado a Unix). Essa linhagem é imperativa: comandos que mudam estado passo a passo. Prolog é declarativo: você descreve fatos e regras, e o motor de inferência decide como resolver, não é "faça isso, depois isso", é "isso é verdade se isso for verdade".

**12.** Fatos: `pai(joao, maria).` `pai(maria, ana).` Regra: `avo(X, Z) :- pai(X, Y), pai(Y, Z).` Consulta: `?- avo(joao, ana).` → verdadeiro. É programação lógica porque a regra não é executada passo a passo, é uma relação lógica que o interpretador usa pra inferir respostas, diferente de só guardar dados numa tabela.

**13.** Ada foi encomendada pelo Departamento de Defesa dos EUA pra sistemas críticos (militares, embarcados). Tipagem forte reduz erros em tempo de compilação, importante quando erro custa caro/vidas. Pacotes (packages) organizam código grande em módulos com interface clara. Concorrência nativa (tasks) porque sistemas críticos rodam múltiplos processos em tempo real simultaneamente.

**14.** Smalltalk: tudo é objeto, puro desde a raiz, sem tipos primitivos separados. C++: adicionou objetos em cima de C, mantendo compatibilidade, por isso é híbrido (pode programar processual ou orientado a objeto), o que trouxe poder mas também complexidade. Java: objetos quase puros como Smalltalk, mas com meta de portabilidade, código compila pra bytecode e roda em qualquer JVM, "write once, run anywhere".

**15.** Java foi criada pra eletrônicos embarcados (controle remoto, dispositivos), não deu certo nesse nicho. Quando a Web explodiu, a portabilidade de Java (bytecode + JVM) encaixou perfeitamente pra rodar applets em navegadores diferentes, contexto novo (Web) aproveitou característica que já existia por outro motivo. Mostra que uma linguagem pode achar seu mercado de verdade em domínio bem diferente do que foi projetada.

**16.** Domínio inicial: Perl (administração de sistemas/processamento de texto Unix), JavaScript (interatividade em páginas Web no navegador), PHP (geração de páginas Web dinâmicas no servidor), Python (uso geral/ensino, depois ciência de dados), Ruby (uso geral, depois Web com Rails), Lua (embarcada em jogos/aplicações, leve). Estruturas de dados: Perl usa arrays/hashes fortes; JS usa objetos/arrays dinâmicos; Python tem listas/dicionários como cidadãos de primeira classe; Lua usa só "tables" pra tudo. Implementação: a maioria interpretada, mas Lua é feita pra ser embutida (footprint pequeno), JS moderno usa JIT pesado (V8). Não são iguais só por serem "scripting", domínios e propósitos originais bem diferentes.

**17.** C# em relação a Java: adicionou propriedades (get/set) como parte da sintaxe, evitando boilerplate de métodos getter/setter que Java exige manualmente. Em relação a C++: eliminou ponteiros inseguros por padrão (código gerenciado, com garbage collector), resolvendo problema de vazamento de memória/ponteiro selvagem que existe em C++.

**18.** XSLT: entrada é XML, processamento aplica templates de transformação, saída é outro documento (XML/HTML/texto), foco em transformar dados. JSP: entrada é requisição HTTP, processamento mistura HTML com código Java embutido, saída é página HTML dinâmica, foco em gerar interface. Ambas são híbridas porque misturam marcação (tags declarativas) com lógica de programação (loops, condicionais) dentro do mesmo documento.

**19.** Linha do tempo (paradigmas: imperativo, funcional, orientado a objetos, lógico): Fortran (imperativo, 1957) → Lisp (funcional, 1958, direção diferente de Fortran) → ALGOL 60 (imperativo, 1960, formalizou sintaxe que influenciaria Pascal/C) → SIMULA 67 (OO, 1967, introduziu classes influenciando Smalltalk) → Prolog (lógico, 1972, resposta declarativa ao paradigma imperativo dominante) → Smalltalk (OO, 1972, OO puro influenciado por SIMULA) → C++ (OO+imperativo, 1985, herda C e adiciona OO de Smalltalk/SIMULA) → Java (OO, 1995, simplifica C++ e herda portabilidade de bytecode). Cada ligação é influência de conceito (sintaxe, paradigma, recurso), não só ordem cronológica.

**20.** Cálculo científico: família Fortran/C (ou Python com bibliotecas numéricas), histórico de otimização numérica e performance. Regras declarativas: família Prolog/lógica, motor de inferência já resolve esse tipo de problema nativamente. Aplicação Web interativa: JavaScript (client) + linguagem server-side tipo Python/Java/C#, histórico de domínio Web. Firmware restrito: C ou Lua, baixo nível/footprint pequeno, sem overhead de garbage collector pesado. Trade-offs: (1) linguagens de alta produtividade (Python) custam performance vs. linguagens de baixo nível (C) que custam tempo de desenvolvimento; (2) linguagens declarativas (Prolog) resolvem certos problemas elegantemente mas têm curva de aprendizado maior que imperativas, então nem sempre compensa usar em toda a equipe.
